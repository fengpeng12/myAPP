# Marco Movie Lite · 第一阶段兼容验证版

作者：Pilipala。GPL-3.0-only。目标 Android 4.0 / API 14 以上。

当前是独立轻量版，不是完整版的功能等价版本；公开安装包以 Releases 附件为准，本地开发签名包不代表正式更新。
包名 `com.pilipala.marcomovie.lite`，可与完整版并存，不读取完整版账号或配置。
本产品只是工具，不含任何影视资源、配置源或账号。用户需自行合法获取配置与内容访问权限。

## 已实现

- 使用真实 API14 平台作为编译 bootclasspath；单 dex、旧安卓可识别的 v1 签名。
- 独立桌面入口、轻量圆角与遥控器焦点、首页返回退出。
- 手机扫码进入局域网配置页；服务仅在配置页开启，离开即关闭。
- 每次配对随机令牌；提交大小限制；下载与解析成功后才保存，失败保留原配置。
- 标准 type 1 JSON CMS 导入、列表分页、单源搜索、详情与线路集数。
- 不支持的类型保留并标识，不伪装成空片库。
- API14 系统 MediaPlayer + SurfaceView 基础播放，确认暂停/继续、单击左右 ±15 秒、返回选集。

- 返回详情前的分类/搜索及页码；保存最近一个播放地址的续播进度。
- 单条来源上移、下移、置顶和删除，修改保存在本机。

## 验收范围与待办

Android 4.0 ARM 模拟器的 33 项集成检查已通过，包含真实系统播放与可选 IJK/FFmpeg 候选解码测试。
配置与 CMS 目录请求（`LiteCatalog.fetch`）支持通过 Conscrypt 启用 TLS 1.2 并带有连接取消与总时限保护；但底层媒体流播放（`MediaPlayer` / `IjkMediaPlayer`）仍受旧系统或候选解码器的 TLS/协议能力限制，不能推论所有现代 HTTPS 媒体流均可直接播放。
尚未进行 Android 4.x 实体电视验收，也没有用私人影视源或网盘账号验证。

下一阶段：

1. 旧系统媒体流 HTTPS（现代证书链、SNI、HLS 分片 TLS 1.2 代理或自带 TLS 的解码栈）与更多编码格式兼容矩阵；禁止关闭证书校验来冒充兼容。
2. JS/JAR/CSP、网页解析、网盘登录与代理逐类适配。
3. 正式海报布局、图片缓存、全局/拼音搜索、自带键盘、历史、收藏及直播。
4. 播放比例、进度 Dock、连续长按快进与完整版交互一致性。
5. Android 4.x 实体旧电视真机验证与低内存长时稳定性测试。

目前单源搜索使用系统输入；每页最多 60 个条目、每条线路最多 150 集，并有明确提示。
播放画面布局、临时图标和长列表还不是最终产品设计。
配置 URL 可使用 HTTP(S)，但系统网络栈不能保证现代 HTTPS 服务兼容；没有引入不安全的证书绕过。

## 本地构建

沿用完整版的 JDK / build tools 配置；设置 `MARCOMOVIE_API14_JAR` 指向官方 API14 android.jar。
默认复用本机 Marco TV 已下载的 API14 平台；其他机器应自行安装并设置环境变量。

```powershell
python scripts/build_lite.py
python scripts/test_lite_device.py
```

测试只连接 `emulator-5580`，并核对其 API 为 14，绝不自动选择家中电视。
测试依赖 FFmpeg 生成合成视频，并在本机 8773 端口临时提供测试配置和媒体，结束关闭。
测试会覆盖 Lite 模拟器内配置，不适用于保存真实账号的设备。
构建产物在 `dist/lite/`；检查报告在 `android/build/lite/`。
APK 使用本地开发签名，公开发行前还需固定正式版本策略及签名备份。

Emby 可从「输入配置地址 → 连接 Emby 媒体库」添加。账户凭据保存在本机专用偏好中，媒体库记录只保存账户引用。支持媒体库、搜索、剧集和原始媒体直连，旧系统的 TLS 与媒体解码限制仍适用。
